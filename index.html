Competenze principali

Tre livelli, un'unica architettura.

Il valore di JDEVPRO è lavorare nel punto in cui normalmente servono più fornitori: software, integrazione con il mondo fisico e gestione operativa del sistema.

01

Software & Systems Integration

Backend, API, database, automazioni e integrazioni tra sistemi aziendali, servizi esterni, provider e dispositivi.

  • PHP · Python · Go · JavaScript
  • REST API · webhook · integrazioni B2B/B2C
  • PostgreSQL · MySQL/MariaDB · Redis
  • RabbitMQ · MQTT · processi asincroni
  • Docker · Linux · CI/CD · logging
02

Industrial & Machine Integration

Collegamento tra software gestionali, macchine, PLC, HMI, gateway e sistemi cloud senza perdere il contesto produttivo.

  • PLC · CODESYS · embedded C
  • RS-485 / RS-232 · MQTT · API macchina
  • Stati, produzione, allarmi e tracciabilità
  • Invio lavori, parametri e comandi
  • Dashboard, scheduler e report economici
03

Connected Infrastructure & IoT

L'infrastruttura necessaria perché software e dispositivi continuino a comunicare in modo affidabile, anche in siti remoti.

  • Linux · networking · VPN · VLAN
  • Wi-Fi · Bluetooth/BLE · gateway edge
  • Sensoristica · telemetria · data acquisition
  • Monitoraggio · alert · accesso remoto
  • Energia, backup e alimentazione remota

ORYVAEL

Sistema operativo AI-native sperimentale in cui l'intelligenza è separata dall'autorità: gli agenti possono costruire e verificare software, ma le capacità privilegiate restano soggette a policy, audit e controllo umano.

La base attuale è un runtime bare-metal x86_64 nativo con boundary ring-3, syscall, capability-checked IPC, RAM filesystem e networking nativo. Il trusted core è sviluppato in Rust.

Profilo

Software engineer prima. Integratore quando serve.

JDEVPRO nasce dall'esperienza di Jacopo Ellero nello sviluppo software e nell'integrazione di sistemi reali. Lavoro tra backend, API, database, infrastruttura, macchine e dispositivi connessi.

Quando il progetto richiede anche rete, gateway, PLC, sensori, energia o hardware, seguo il flusso tecnico end-to-end invece di separare artificialmente software e infrastruttura.

Questo approccio è particolarmente utile nei sistemi esistenti: integrazioni con vincoli reali, software legacy, macchine di terzi, API imperfette, ambienti di produzione e progetti nei quali il problema non appartiene a una sola disciplina.
