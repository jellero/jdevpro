Research · AI-native operating system

ORYVAEL: AI does the work, people stay in charge.

ORYVAEL is an AI-native operating system: AI can design, write, test, integrate and maintain software, while authority always remains explicitly with people.

ORYVAEL website ↗Code on GitHub ↗Let's talk

The idea

Separate intelligence from authority.

  • Scoped
  • Observable
  • Attributable
  • Reproducible
  • Reversible

ORYVAEL does not assume that an AI becomes trustworthy enough to receive unrestricted access. It assumes the opposite: AI components are powerful but untrusted.

Every action must be scoped, observable, attributable, reproducible and reversible. No AI model belongs to the system's root of trust.

Boundaries

What AI can do, and what it cannot.

AI can

  • analyse requirements and propose architecture
  • write code and tests
  • run builds and security analysis
  • prepare releases
  • diagnose failures and propose fixes

AI cannot

  • grant itself permissions
  • change the system's core rules
  • touch the root of trust
  • disable the audit log
  • skip mandatory verification
  • sign privileged releases or expand its own scope

Every change

Whoever writes the code cannot approve it.

  1. Human intentA person defines the need and approves the plan.
  2. Scoped permissionThe AI receives only the permissions that task needs.
  3. ImplementationThe AI writes and tests the change in its isolated space.
  4. Independent verificationSeparate checks produce evidence for the change.
  5. Staged rolloutDeterministic rules decide; release advances in stages.
  6. Signed recordEvery step stays traced and verifiable.

Profiles

Same trust model, different devices.

Desktop

Isolated workspaces, local AI agents, explicit permissions; x86-64 and ARM64.

Mobile

ARM64, low power, secure-element identity, same rules as desktop.

Embedded and edge

IoT, robotics and gateways: on-device permission enforcement, signed updates and rollback, Rust for microcontrollers.

Status

The foundations already run on hardware.

  • Rust kernel booting directly from UEFI on x86-64, with no Linux underneath
  • Its own memory management, user processes, timer and system calls
  • Native networking: DHCP, DNS, ping and TCP
  • SSH remote access with Ed25519 keys only; passwords and root disabled
  • Native graphics and automatic build and boot verification on every change

It is not yet a production operating system and does not yet include a native AI engine: it is ongoing, documented and verifiable research.

Why it matters

The same principle, in clients' systems.

  • Least privilege
  • History of every action
  • Independent checks
  • Rollback to the previous version

ORYVAEL is research, but its principle guides every system we build: automation yes, with least privilege, a history of every action and the ability to roll back.
