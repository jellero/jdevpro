Integrare un sistema senza API: le strade possibili.

Molti software e dispositivi non hanno API pubbliche. Non significa che non si possano collegare: significa scegliere la strada giusta e renderla affidabile.

1. API pubbliche, quando ci sono

È la strada migliore: integrazione completa in lettura e scrittura, con eventi e webhook e credenziali ufficiali. Prima di tutto verifico se il sistema le offre, anche a pagamento o su richiesta al produttore.

2. Interfacce web senza API pubbliche

Se un servizio si usa dal browser, il browser parla con il server attraverso chiamate precise. Posso automatizzare le stesse chiamate: accesso, lettura dei dati, invio dei comandi.

  • prima verifico le condizioni d'uso del servizio;
  • uso un account dedicato, con i permessi minimi;
  • controllo automatico che le chiamate funzionino ancora dopo gli aggiornamenti del servizio;
  • avvisi immediati se qualcosa cambia.

3. Seriale e Modbus

Macchine, inverter, contatori e sensori industriali spesso parlano solo su porta seriale RS-485 o RS-232, spesso con protocollo Modbus RTU, oppure su Modbus TCP in rete. Un piccolo middleware legge i registri del dispositivo e porta i dati nel sistema aziendale tramite API o MQTT.

  • il middleware gira su un PC industriale, un NAS o un gateway dedicato;
  • i dati vengono conservati localmente se la rete cade;
  • la mappa dei registri viene documentata, così chiunque può verificarla.

4. File, database e cartelle condivise

Molti gestionali esportano file (CSV, XML, Excel) o scrivono in un database. Si possono leggere e scrivere in modo controllato, con anteprima, controllo dei duplicati e storico delle importazioni.

Come scelgo la strada

In ordine: API ufficiali, poi file o database, poi interfacce web, poi seriale o Modbus per i dispositivi fisici. Scelgo la strada più stabile e più facile da mantenere, non la più veloce da scrivere.
