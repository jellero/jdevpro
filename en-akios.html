Product · IoT firmware and lifecycle

AKIOS: IoT devices that update without breaking.

AKIOS is a layer living inside the device that governs its whole lifecycle: first setup, updates, rollback to the last good version and recovery. For European manufacturers who must guarantee secure updates for years, without changing cloud.

AKIOS website ↗Pilot programme ↗Let's talk

The problem

Every product line rebuilds the same things.

As devices grow across models and chips, lifecycle failures stop being isolated engineering issues and become support cost and field risk.

Different firmware per chip

Variants, regressions and inconsistent behaviour to maintain for years.

Risky updates

A failed update can brick the device: support, returns, lost customers.

Fragile setup

First setup fails in the field and nobody knows why.

New obligations

The EU Cyber Resilience Act requires security updates for the whole support period and documented evidence.

How it works

Trial, commit, rollback, recovery.

  1. Signed updateEvery version is verified with a digital signature (ECDSA P-256) and SHA-256 hash before being accepted.
  2. Controlled trialThe new system starts in a separate slot: the last good version stays intact.
  3. Commit or rollbackIt is committed only if health checks pass; otherwise the device rolls back by itself.
  4. Local recoveryIf no valid system is left, the device opens a protected Wi-Fi network and is restored from a phone.

The principle

Every update always leaves a way back.

  • Two separate system slots (A/B)
  • Redundant state data
  • Health check after every update
  • Protected local recovery network
  • No forced cloud: yours stays

An update can never overwrite both the AKIOS BIOS and the last committed system. Interrupted uploads, invalid signatures, corrupted versions or failed trials cannot replace the good system.

The AKIOS BIOS takes care of device survival; the system, with product logic and cloud connections, is replaceable and signed separately.
